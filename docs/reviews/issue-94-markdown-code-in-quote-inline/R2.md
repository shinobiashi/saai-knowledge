再実測（53 ケース）で生の HTML が残ったのは、拡張なしの pymd のトップレベルのフェンス（既知の制約）と、差分範囲外の R1-X2（backlog）だけ。`not shown as text` の一部は制御文字を含む入力でのチェッカーの表示（生の HTML ではない）。

`href` の無い `<a>` を trim しなくなった影響は、コードを含まない普段の形（`<h2><a id></a>Section</h2>`・空の `<a name>`・中の空白・`<div>` の行頭の `# …`）で main と同じ出力であることを確認した（自己検証）。独立レビューも、行頭の空白がフェンス・見出しの前に残る形は作れなかったと報告。`writes_inline_syntax()` と `a` の case はどちらも `link_href()` を使うので、`href="  "`・`HREF=" "`（アンカー扱い）と `<A HREF="…">`・`href="#"`（リンク扱い）で判定が揃う。

## 指摘

### [R2-2][Medium][plugins/saai-knowledge/tests/test-markdown-converter.php（`test_code_block_inside_a_quote_is_a_code_span`）]

引用の `pre` の空の分岐を外しても、既存のアサーション（空の `<pre>` が引用の末尾）は `trim()` で差が消えて通る（独立レビューのミューテーションで NOT CAUGHT）。独立レビューは Low としたが、テストの欠落なので重大度の定義どおり Medium とし、その場で修正した。

**対応:** 空の `<pre>` を2つの段落の間に置いた `assertSame( "> a\n> \n> b\n", … )` を追加。同じミューテーションが CAUGHT になることを確認
