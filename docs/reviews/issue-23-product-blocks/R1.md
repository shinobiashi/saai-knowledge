## 指摘

### [R1-1][High][plugins/saai-knowledge-for-woocommerce/src/shared/product-picker.js:63,73]

core-data は投稿タイプのエンティティを既定で `context=edit` で取得する（WP 7.1.3 の `core-data.js` の `baseURLParams`）。商品権限（`edit_products`）を持たない Editor では `/wp/v2/product?context=edit` が 403（`rest_forbidden_context`）になり、ピッカーで検索も選択済み商品の名前表示もできない。`context=view` なら 200（Editor ユーザーで `rest_do_request` を実測）。DESIGN §6.1 が core REST を選んだ理由（Editor でも動く）と矛盾する。E2E は属性をプログラムで入れており、ピッカーの UI は検証されていない。
**修正方針:** 両クエリに `context: 'view'` を付け、Editor ロールでピッカーを操作する E2E を追加する。

### [R1-2][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-product-sections.php:349, src/product-glossary/render.php:35]

ブロックが投稿本文（商品説明・固定ページ）にあると、`the_content` の `do_blocks`（9）の出力に `do_shortcode`（11）が掛かる。定義文の `[x]` が実行される（手動抜粋はそのまま、本文由来は `strip_shortcodes()` が `[[x]]` を `[x]` に戻すため）。サブエージェントのプローブで `<dd>` 内にショートコードの出力が描画されることを確認。DESIGN §6.2 の「定義内のショートコードを実行しない」に反する。タイトルも同じ経路に乗る。影響は角括弧を含む定義・タイトルに限られるため Medium とした。
**修正方針:** ブロック出力のテキスト（タイトル・定義）は `esc_html()` 後に `[` / `]` を `&#91;` / `&#93;` にする。`the_content` 経由で検証するテストを追加する。

### [R1-3][Medium][plugins/saai-knowledge-for-woocommerce/src/product-*/index.js（noProductText）]

サイトエディターで単一商品テンプレートを編集すると `post_id` が渡らず、常に「Choose a product in the block settings to preview it here」が出る。`productId` はプレビュー専用ではなく共有テンプレートに保存される属性なので、従うと全商品ページに特定商品の FAQ（と FAQPage）が出る。
**修正方針:** 文言を「テンプレートでは空のままにする。特定商品を出すのは通常ページなど」と明記する形に改める。

### [R1-4][Medium][plugins/saai-knowledge-for-woocommerce/tests/test-woo-product-blocks.php]

テスト欠落・トートロジー: `for_block( 'not a number', … )` は `is_numeric` ガードを外しても `(int)` で 0 になり何も固定しない。`for_block` の `is_search()` / `is_home()` 分岐を通るテストが無い。R1-2・R1-5 のケースのテストも無い。
**修正方針:** `'<ID>abc'` 形式（ガードが無いと別商品に解決される）に置き換え、検索・投稿ページのルートのケースと R1-2 / R1-5 のテストを追加する。

### [R1-5][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-shortcodes.php:124,130]

ドキュメント（DESIGN §6.2）と実装の不一致: `show_title=""` は `FILTER_VALIDATE_BOOLEAN` が `false` を返し見出しが消える（仕様は「それ以外は既定値」）。`product_id="12abc"` は `(int)` で 12 に解決され、テストの docblock の「数値でない値は未指定扱い」と食い違う。
**修正方針:** 空文字は既定値に任せ、`product_id` は `is_numeric()` を満たすときだけ採用する。
