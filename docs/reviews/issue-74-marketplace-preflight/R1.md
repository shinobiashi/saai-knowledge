## 指摘

### [R1-1][High][plugins/saai-knowledge-for-woocommerce/changelog.txt:3 / bin/verify-woo-zip.sh:73,76 / docs/DESIGN.md §6.3]
`changelog.txt` の書式が WooCommerce.com の公式書式（`YYYY-MM-DD - version x.y.z`。[changelog.txt](https://developer.woocommerce.com/docs/extensions/core-concepts/changelog-txt/)）と違い、WordPress.org の readme 風の `= 1.0.0 - 2026-10-10 =` になっている。Product update guidelines は「The changelog.txt file provided does not match the expected format」をアップロード失敗の理由に挙げており、検証スクリプトと DESIGN.md がこの誤った書式を固定・強制していた（出所は共有スキル woo-marketplace-submission の例）。
**修正方針:** changelog を公式書式（エントリ種別も例の `Added` 等）にし、検証の正規表現・エラーメッセージ・DESIGN §6.3 を合わせる。

### [R1-2][Medium][plugins/saai-knowledge-for-woocommerce/readme.txt:42-44]
readme の「an Editor does not need WooCommerce's product permissions」は、Linked Products パネルの `context: 'view'`（Issue #71、未マージの PR #73）が入って初めて正しい。このブランチだけで ZIP を作ると誤った説明が出荷され、QIT マトリクスの E2E にもパネルの spec が含まれないため未検証のまま。
**修正方針:** 申請前チェック（`docs/MARKETPLACE-PREFLIGHT.md` の「申請時に確認すること」）に「#73 がマージ済みで、`bin/qit-matrix.sh` の E2E に `linked-products-panel.spec.js` が含まれていること」を加え、PR 本文にもマージ順の依存を書く。

### [R1-3][Medium][bin/qit-matrix.sh:117-143,189-196]
エラー処理の不足で、1 組の失敗がマトリクス全体を止める。
- `sed … | head -n 20` が `pipefail` 下で SIGPIPE（141）になり `set -e` で中断する（debug.log が大きい失敗時。サブエージェントが 20 万行で再現）
- 商品・FAQ の作成、`post meta add`、env.json の解析が `||` の外にあり、失敗するとサマリーを出さずに中断する。env.json の解析に失敗すると `ENV_ID` が空のままで、環境（Docker コンテナ）が取り残される
- ID を `tr -dc '0-9'` で取るため、混入した出力の数字が連結されうる

**修正方針:** `head` を先にかける。各ステップに `|| STEP_FAILED=1` を付ける。ID は最終行を数値か検証して取る。env.json の解析に失敗しても `qit env:down --all` しないで済むよう、ENV_ID を先に取り失敗を記録して続行する。

### [R1-4][Medium][docs/MARKETPLACE-PREFLIGHT.md]
Issue #74 の受け入れ条件（「ローカルの QIT 相当チェック（Activation 相当・Plugin Check・PHPCompatibility）でエラー・notice ゼロ」）のうち、PHPCompatibility の結果が記録されていない。また Plugin Check の手順が `mkdir dist/woo-check` で、`dist/` が無いときや 2 回目に失敗する。
**修正方針:** PHPCompatibility（`composer lint` に含まれる `PHPCompatibilityWP`、testVersion 8.2-）の結果を記録し、手順を再実行できる形にする。
