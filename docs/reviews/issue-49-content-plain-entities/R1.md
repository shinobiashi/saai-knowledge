## 確認したが問題なしと判断した観点

- デコードはタグ除去の後・空行圧縮と trim の前。`&lt;br&gt;` は改行に化けず、`&#10;` の連続も 2 行に圧縮される。
  `&amp;lt;` は 1 回だけデコードされる
- `&#0;` `&#13;` `&#128;`〜`&#159;` サロゲート等は ENT_HTML5 ではデコードされずそのまま残る（C1 は
  `the_content` の `convert_chars` が事前に変換済み）。不正な UTF-8 は変更前と同じくそのまま通る
- `title` と同じフラグ・同じ順序。DOMDocument 経路の `content_markdown` もデコード済みテキストを出すため、
  `content_plain` だけが文字参照を含んでいた不一致が解消
- テストの有効性: デコードを外すと 3 件、タグ除去の前でデコードすると `&lt;br&gt;` の 1 件が失敗（実測）。
  export のテストは `the_content`（wptexturize の `&#8217;`）を実際に通す
- export レコードはキャッシュされない（`Markdown_Output::render()` の非キャッシュ版を使う）ので、
  更新後のリクエストからすぐ反映される
