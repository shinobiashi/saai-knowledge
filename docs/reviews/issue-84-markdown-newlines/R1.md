## 指摘

### [R1-1][Medium][plugins/saai-knowledge/includes/class-markdown-converter.php（`render_code_fence()` / `blockquote` / `escape_table_cell()`）]

独立レビューの範囲外指摘（1.0.0 からの既存挙動）を、ユーザー判断でこの PR の範囲に含めた。`<pre>` の textContent に残る単独の CR（`&#13;`。kses と `the_content` を通っても残る）を、引用は `explode( "\n" )`、表のセルは `"\n"` の置換でしか扱わない。描画系は CR も改行として読むので、引用では CR の後ろの行に `> ` が付かずに引用とフェンスの外へ出て、表ではセルの行が割れる。`<blockquote><pre><code>a&#13;&lt;img src=x onerror=alert(1)&gt;</code></pre></blockquote>` は commonmark / markdown-it で、`<td><pre>a&#13;&lt;img …&gt;</pre></td>` は markdown-it / pymd-extra で生の `<img onerror>` になる（実測。`<pre>` 単体は合格）。#84 と同じ種類の5つ目の経路で、`unfiltered_html` の無い投稿者でも書ける。

**修正方針:** `render_code_fence()` の先頭でコードの `\r\n` / `\r` を `\n` にする（フェンスの中なので見た目は変わらない）。`escape_table_cell()` も `\r` を空白にする。

### [R1-2][Low][plugins/saai-knowledge/includes/class-markdown-output.php（`meta_lines()` の Category 行）]

独立レビューの範囲外指摘を、ユーザー判断でこの PR の範囲に含めた。ターム名の `&#10;` は保存時の `sanitize_text_field()` を素通りし（`Cat&#010;~~~` のまま保存される。wp-env で実測）、デコードすると改行になるので、`**Category:** Cat` の次の行の `~~~` がフェンスを開いて本文のコード例の `~~~` で閉じ、フェンスを読む4描画系で生の `<script>` になる（独立レビューの実測）。カテゴリーを作れるのは `manage_categories`（編集者以上）だけなので Low。タイトル・サイト名・セクションの見出しと同じ扱いの漏れ。

**修正方針:** タイトルと同じく、デコードした後に `\r` / `\n` を空白にしてから `escape_text()` に渡す。

### [R1-3][Medium][plugins/saai-knowledge/tests/test-export.php（`test_section_heading_line_endings_become_spaces()`）]

`assertSame( 'setup', …anchor )` は、`matching_anchor()` の照合が成功しても失敗しても通る（Heading_Anchors の id も照合失敗時の代替も `sanitize_title()` で作るので、どちらも `setup`）。テストの docblock が言う「`heading` フィールドを変えないので Heading_Anchors との照合が保たれる」ことを固定できていない（独立レビューの L1。この PR の設計判断のガードなのでテスト欠落として Medium に上げた）。

**修正方針:** 見出しブロックに明示の `anchor` 属性（`id`）を付け、照合が成功した時だけその id になることを確かめる。
