## 指摘

### [G3-1][Codex][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-links-controller.php:331]

`posts_per_page` は SQL の `LIMIT` になるため、権限フィルタ（`visible_items( ..., 'edit_post' )`）が
打ち切り後の1ページに対して走る。他人の投稿が先にソートされると、編集可能な候補が存在しても
結果が空または要求件数未満になり、**自分の投稿を商品に追加できない**。

**これは G2-2 で自分が入れた修正が実害化させたもの。** R1 の時点で同じ箇所を backlog（R1-B4）に
入れながら「この画面に到達できるロールは `edit_others_posts` を持つので発火しない」と判断しており、
G2-2 で検索フィルタを `edit_post` に変えたことでその前提を自分で壊していた。

判定: 修正
**対応:** `perm => 'editable'` + 明示的な `post_status` 配列でクエリ段階へ制約を移動。
**要点**: `post_status => 'any'` のままでは `perm` が効かない — core は `in_array( 'any', $q_status )` の枝で
除外条件しか組み立てず `$r_status` が空のままなので、`perm` を適用する分岐に到達しない
（`class-wp-query.php:2666-2696`）。最初の実装はこれで no-op になり、追加したテストが落ちて発覚した。
ミューテーション（`perm` 行削除）で `test_content_search_is_not_truncated_by_uneditable_matches` が
落ちることを確認。backlog の R1-B4 を「解消」に更新（`3fb132f`）/
スレッド: https://github.com/shinobiashi/saai-knowledge/pull/64#discussion_r4093936206

### [G3-2][Copilot（レビュー本文・スレッドなし）][—][assets/js/linked-products-panel.js:155, 285]
