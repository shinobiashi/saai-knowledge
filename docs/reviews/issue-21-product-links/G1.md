### [G1-1][Codex][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-links-controller.php:439]

パスワード保護された公開投稿は `post_status` が `publish` のままなので、R2-4 で
`protected_title_format` の接頭辞を外した結果、商品メタボックスから保護状態を知る手段が
完全に失われていた（ステータスバッジは `publish` 以外のときだけ表示されるため）。
実機スクリーンショットでも「KB記事」バッジのみが出ていることを確認済み。
**前ラウンドで自分が入れた修正の副作用**を bot が捕まえた形。

判定: 修正（接頭辞を戻すのではなく専用フィールドで返す。接頭辞は `status_label` と二重になるため）
**対応:** `protected` フィールド + メタボックスのバッジ + テスト2本（`ec93757`）/
スレッド: https://github.com/shinobiashi/saai-knowledge/pull/64#discussion_r4092540782

### [G1-2][Copilot][—][plugins/saai-knowledge-for-woocommerce/includes/class-links-controller.php:561]

`absint` が負の `content_id` を正値化して `minimum` 検証へ渡す、という指摘。

判定: **誤検知**。`WP_REST_Server::dispatch()` は `has_valid_params()` を `sanitize_params()` より
先に実行するため（WP 7.1.2 `class-wp-rest-server.php:1115` → `:1119`）、`minimum => 1` が先に 400 を返し
`absint` には到達しない。URL 埋め込み側は `[\d]+` で負号にマッチしない。実測で確認済み。
**対応:** 保留（未解決のまま返信）。ただし安全性が実行順序に依存する点は妥当な懸念なので、
`content_id: -3` が 400 かつメタ行が作られないことを固定するテストを追加した /
スレッド: https://github.com/shinobiashi/saai-knowledge/pull/64#discussion_r4092544845
