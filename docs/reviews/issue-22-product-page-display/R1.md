## 指摘

### [R1-1][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-product-page.php:260]
`kb_links_html()` は `Link_Resolver::content_ids_for_product()`（`fields => 'ids'` で投稿キャッシュを温めない）の結果に対し、記事ごとに `get_permalink()` / `get_the_title()` を呼ぶため、紐づけ KB の件数分 `get_post()` のクエリが走る（N+1）。KB のパーマリンクはカテゴリーを埋め込むのでタームも同様。
**修正方針:** ループの前に `_prime_post_caches( $kb_ids, true, false )` で投稿とタームを一括プライムする。テストで投稿キャッシュを事前に消し、描画後に両記事が `posts` グループに載っていることを固定する。

### [R1-2][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-product-page.php:177-181]
`faq_list_html()` が `faq_tab_available()` 経由で `faq_ids()` を呼んだ直後に `post__in` 用にもう一度 `faq_ids()` を呼ぶため、商品ページ 1 回の描画で同じ meta JOIN の WP_Query が重複する（`add_faq_tab()` の 1 回と合わせて 3 回）。さらに `WP_Query` は空の `post__in` を「制約なし」と解釈するので、「空でないことを別の呼び出しで確認してから再取得する」構造は、再取得側が空を返した瞬間に全 FAQ をタブへ出す事故と紙一重（サブエージェント A-1）。
**修正方針:** `faq_tab_available()` を設定・ブロック登録だけを見る `faq_tab_enabled()` にし、`faq_list_html()` は ID を 1 回だけ取得して空なら自分で `''` を返す（クロージャが空配列を見ることはない）。残る呼び出し回数（FAQ 2・KB 1・辞書フィルター 2〜3）はいずれも小さなクエリで、リクエスト横断の陳腐化リスクを持つメモ化を入れるほどではないと判断（永続ワーカーでの寿命管理が必要になる。CLAUDE.md の注意事項）。

### [R1-3][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-product-autolink.php:179-193]
`woocommerce_short_description` は短い説明テンプレートだけでなく、WC の汎用整形関数 `wc_format_content()` も経由する（実ソースで確認: `class-wc-product-variable.php:499` の variation 説明、`FeaturedProduct.php:120`、`FeaturedCategory` / `CategoryDescription` ブロック、`CartItemSchema` 等）。単一商品ページ上では (1) 可変商品の variation 説明が `data-product_variations` の JSON に自動リンク付きで埋め込まれ、選択時に jQuery が DOM へ挿入するため Interactivity API にハイドレートされず、アンカーは付くがツールチップは開かず `aria-describedby` / `aria-expanded` が死んだ属性として残る一方、`has_rendered_links()` は true になり資材が読み込まれる。(2) 同じページに置いた Featured Product ブロックの別商品の文章が、表示中商品の紐づけ辞書でリンクされる（サブエージェント A-2）。
**修正方針:** `wc_format_content` がコールスタック上にある呼び出しをスキップする（`debug_backtrace()` で関数名を照合。`doing_filter( 'woocommerce_format_content' )` は内側のフィルターが先に評価されるため使えない。無料版 `Autolinker::is_inside_wp_trim_excerpt()` と同じ手法）。テストでは WooCommerce 不在のため `wc_format_content()` の 1 行実装を同名で定義して経路を再現する。DESIGN-AUTOLINK.md §6 に経路の除外を明記。

### [R1-4][Medium][plugins/saai-knowledge-for-woocommerce/tests/test-woo-product-page.php, tests/test-woo-product-autolink.php]
差分が導入した主張・ガードに対する PHPUnit が不足（サブエージェント A-3）: (i) `Product_Context::current_product_id()` の docblock と DESIGN.md §6.2 は「REST block-renderer プレビューを除外する」と主張するが、REST 文脈で 0 を返すテストが無い。(ii) R1-3 の `wc_format_content()` 経路のテストが無い。(iii) `faq_list_html()` の `$restrict` クロージャの `! is_array( $args )` 分岐が未到達——しかも現状の「そのまま返す」実装では、無料版 `Faq_List::query_args()` が非配列を受けると**無制限の既定 args にフォールバック**するため、サードパーティの壊れたコールバック 1 つで商品タブに全 FAQ が出る。
**修正方針:** (i) `rest_route` クエリで `go_to()` し、グローバル `$post` を商品にプライムした状態で 0 を assert。(ii) R1-3 のテスト。(iii) 非配列を受けたらブロック自身の制約（`post_type` / `publish` / `has_password=false` 等）を自前で組み立てた上で `post__in` を課すよう修正し、priority 10 で非配列を返すコールバックを一時登録しても紐づけ FAQ だけが出ることを固定する。
