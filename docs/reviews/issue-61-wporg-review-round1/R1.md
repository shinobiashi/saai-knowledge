## 指摘

### [R1-1][Medium][bin/i18n-build.sh:21-23]

今回追記した「ローカルで翻訳を試す手順」のコピーコマンドが `saai-knowledge-ja.*` というグロブになっており、JS 翻訳 JSON（`saai-knowledge-ja-<md5>.json`。`ja` の後が `.` ではなく `-`）にマッチしない。手順どおりに実行すると PHP 側だけ翻訳され、ブロックエディタ等の JS 文字列は無言で英語のまま残る。このスクリプト自体の主目的が「`make-json` のハッシュ問題」なので誤誘導の害が大きい。

Claude 本体・サブエージェントの双方が独立に検出。実機確認: 手順どおり実行後、コンテナの `wp-content/languages/plugins/` には `.mo`/`.po`/`.l10n.php` の3件しか入らず、`load_script_textdomain()` が `false` を返す。`-*.json` も併せてコピーすると ja の locale_data を返すことを確認済み。

**修正方針:** グロブを `saai-knowledge-ja*`（ドット無し）に変更する。

### [R1-2][Low][docs/DESIGN.md:287]

「有料版（WooCommerce.com 配布）: `load_plugin_textdomain()` と `languages/` 同梱を**継続する**」と書いたが、`plugins/saai-knowledge-for-woocommerce/` に `languages/` は存在せず、同梱は「継続」ではなく「未実施」。`load_plugin_textdomain()` の呼び出しだけが実在する。

**修正方針:** 「同梱は M5 以降で `languages/` を用意する前提の方針」と将来形に直す。

### [R1-3][Low][plugins/saai-knowledge/readme.txt:60]

**修正方針:** 検証済みの事実だけを書く（「CI は Node.js 24 でビルドしている」）に改める。未検証の下限バージョンを新たに主張しない。

## 検証したが問題なし

- **翻訳の回帰なし**: `wp-content/languages/plugins/` に言語パック相当を置いた状態で、CPT ラベル（`ナレッジベース`）、タクソノミーラベル（`カテゴリー`）、`block.json` の `title`（`FAQリスト`）、`load_script_textdomain()`（`assets/js/glossary-panel.js` と `build/faq-list/index.js` の両方）がすべて ja を解決することを実機確認。`debug.log` に「Translation loading … triggered too early」も出ない（サービスのコンストラクタに翻訳関数呼び出しが無いことも確認）。
- **CLAUDE.md:100 の技術的主張は正確**: `WP_Textdomain_Registry::get_paths_for_domain()` が `WP_LANG_DIR/plugins` / `WP_LANG_DIR/themes` / `custom_paths` の3つだけを返すことを、コンテナの WP 7.1 と wordpress-develop 6.9 の双方で確認。
