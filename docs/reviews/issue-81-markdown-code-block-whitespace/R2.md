## 新規指摘（R1 の修正で混入したもの）

### [R2-1][Low][plugins/saai-knowledge/includes/class-markdown-converter.php（`convert_children()`）] → R2 で修正

`end_block()` がインライン要素の子にも効くので、`[…](…)` / `**…**` の内側に空行が入る。Custom HTML のカード `<a href="u"><div>Title</div><div>Desc</div></a>` が、main の `[TitleDesc](<u>)` から `[Title\n\nDesc](<u>)` になり、リンクが壊れて括弧が見えるようになった（実測）。生の HTML は出ない。

**対応:** R1-2 の空行は、安全のためにはコードのフェンスが行頭から始まれば足りる。そこで `starts_new_block()` を足し、親がインライン要素のときは「コードブロックそのもの」か「それを含むブロック」の前だけに空行を入れるようにした。カードは main と同じ1行のリンクに戻る（`test_inside_inline_element_only_code_starts_a_new_block`）。ミューテーション3つ（常に空行を入れる・`pre` の判定を外す・子孫の `pre` の判定を外す）がすべて CAUGHT。DESIGN §7.3・CLAUDE.md に追記した。

### [R2-2][Low][bin/markdown-render-check.sh（`PRE_TEXTS`）] → backlog

`<td>` の中の `<pre>` のコードに `|` があると、`escape_table_cell()` の `\|` がコードスパンに残る。表に対応しない commonmark は `ls \| grep x` と表示するので、新しい `<pre>` の文字の検査が `FAIL not shown as text: 'ls | grep x'` になる（markdown-it は ok。サブエージェントが実測）。変換器の既存の挙動に対する、スクリプト側の誤検知。

### [R2-3][Low][bin/markdown-render-check.sh（`handle_starttag`）] → backlog

`javascript:` を検出したときの報告にスキームをそのまま出すので、`JAVA<TAB>SCRIPT:` の制御文字が端末に出る。表示だけの問題で、正規化後の文字列か `repr` で出せばよい。

## 対象外指摘（差分範囲外。backlog へ）

- [R2-X1][Medium][plugins/saai-knowledge/includes/class-markdown-converter.php（`blockquote`）] core/quote の中のコードブロック（`` > ``` ``）を Python-Markdown は `fenced_code` / `extra` があっても認識しない。コードに空行が無ければ偶然コードスパンとして文字で出るが、空行を含むコード（`a\n\n<script>y</script>`）は生の `<script>` になる（サブエージェントと自分で実測。commonmark / markdown-it は ok）。main と同じ Markdown（1.0.0 から）。R1 で「引用は合格」としたのは空行の無いコードだった。readme 1.0.3 のサニタイズの案内と DESIGN §7.3 に、引用の中は拡張があっても読まれないことを書き足した
