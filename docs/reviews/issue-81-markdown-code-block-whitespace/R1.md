## 指摘

### [R1-1][Medium][bin/markdown-render-check.sh:189-232]

解析が「Markdown が作らないタグがあるか」しか見ないため、Markdown も作るタグだけでできた生の HTML を見逃して `ok` と報告する。行頭に空白の付いたフェンスの中の `<p onmouseover=alert(1)>hi</p>` を pymd-fenced で描画すると、生の `<p onmouseover>` が出るのに `ok` だった（サブエージェントと自分で実測）。コード例に `<p>` / `<a>` / `<img>` が含まれるのは普通なので、このスクリプトの主な用途で合格が信用できない。

**修正方針:** タグごとに、Markdown が付ける属性だけを許す（`a`: href・title、`img`: alt・src・title、`ol`: start、`code`: class、`th` / `td`: align・style）。それ以外の属性と `javascript:` / `vbscript:` の URL も生の HTML として報告する。`--from-html` では入力の各 `<pre>` の中身が文字として出ていることも確かめ、タグも属性も Markdown と同じ形のコード例（`<p>hi</p>`）が段落として描画されたことも検出する。

### [R1-2][Medium][plugins/saai-knowledge/includes/class-markdown-converter.php（`convert_children()`）]

サブエージェントの範囲外指摘（1.0.0 からの既存挙動）を、ユーザー判断でこの PR の範囲に含めた。ブロック要素は出力の末尾にしか空行を置かないため、直前に地のインライン要素があると構文が行の途中から始まる。`<p>Intro</p>\n<span>stray</span>\n<pre>…&lt;script&gt;…</pre>` は `stray ```\n<script>…` になり、**5 つの描画系すべて**（CommonMark 系も含む）で生の `<script>` になった（実測）。`<dl><dt>T</dt><dd><pre>` は `` T ``` `` になる。リンク付き画像の後の `<figcaption>` はキャプションが連結する。`stray<hr>` は setext の見出しになる。Custom HTML ブロック・ショートコードの出力・wpautop の掛からないクラシック本文で起こりうる。#81 と同じ脅威モデルで、DESIGN §7.3 に追記した「フェンスと見出しは行頭から始める」もこれを直さないと成り立たない（サブエージェントの R1-7）。

**修正方針:** `convert_children()` で、ブロック要素（`BLOCK_ELEMENTS`。`BLOCK_CONTAINERS` を改名し、Markdown のブロックを出す要素を足した）を足す前に、それまでの出力が空行で終わっていなければ空行を補う（`end_block()`。末尾の空白は落とす）。readme 1.0.3・DESIGN §7.3・CLAUDE.md の記述を合わせる。
