### [G3-2][Codex][Medium][plugins/saai-knowledge/includes/class-markdown-converter.php:579]

`escape_line_start()` が行頭の `~~~` をエスケープしないので、`<div>intro<div>~~~</div><div>hidden</div></div>` の `~~~` がチルダのフェンスを開き、残りの本文がコードとして取り込まれる。さらに、そのフェンスが後ろにある変換器自身のコードブロックを取り込み、コード例の中の `~~~` 行で閉じると、残りの `<script>` がフェンスの外に出る（`<p>~~~</p><pre><code>~~~\n&lt;script&gt;…` で、commonmark.js でも生の `<script>` が出ることを再現。`<p>~~~</p>` の形は main から）。/ 判定: 修正

**対応:** 72af1b4 で、行頭の `~~~` の先頭の `~` を `&#126;` にした（Python-Markdown は `\~` をエスケープとして扱わないので文字参照にした）。バッククォートのフェンスは、`escape_text()` がすべてのバッククォートをエスケープしているので対応は要らない / スレッド: https://github.com/shinobiashi/saai-knowledge/pull/83#discussion_r4241727056

テストは `test_inline_content_at_the_start_of_a_line_escapes_markers_and_tilde_fences` を追加した（`<span>` の `#`、ご指摘の `~~~`、抜け道の例、`<br>` を2つ続ける例）。ミューテーション3つ（`~~~` の置換を外す・インライン要素を対象から外す・`<br>` の除外を外す）がすべて CAUGHT。描画比較は 21 入力 × 4 描画系がすべて合格。PHPUnit 612 件。
