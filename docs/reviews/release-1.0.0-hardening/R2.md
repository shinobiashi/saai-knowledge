### 検証の深掘り（アサーションの実効性）
「1回目呼び出しの返り値が2回目実行後も無事か」を確認する最後のブロックは、`find_node()` が値渡し（配列コピー）であり `build()` も参照返し宣言ではないため、PHPの言語仕様上、`$first_parent_node`/`$first_other_node` を再代入しない限りテスト自身のローカル変数として独立している。この点だけを見ると一見トートロジー的に見えるが、以下の現実的なリグレッション種別のどちらに対しても実際に検知力があることを確認した。

1. **テストのdocblockが名指しする将来リファクタ**（ノードに `\WP_Term`/`\WP_Post` オブジェクトを値ではなく参照で持たせる設計変更）: PHPのオブジェクトはハンドル共有のため、配列コピーを介しても同一オブジェクトを指し続ける。したがって `apply_expansion()` がオブジェクトのプロパティを直接書き換えるようになった場合、`$first_parent_node` 経由でもその汚染が観測でき、テストは失敗する。
2. **より現実的なリグレッション**（`current_post_id` ごとの差異を無視して展開済みツリーをインスタンスにメモ化してしまうバグ等、`build()` の2回目呼び出しが1回目の結果をそのまま使い回してしまうケース）: この場合は2回目呼び出し自身の値（`$second_parent_node`/`$second_other_node`）が期待通り反転せず、既存の中段アサーション（`assertFalse($second_parent_node['expanded'])` 等）がそのまま失敗として検知する。

いずれのケースでも本テストは有効に機能し、「常に自明に真となるvacuousなアサーション」には該当しないと判断した。

`apply_expansion()`/`build()`（`plugins/saai-knowledge/includes/class-sidebar-tree.php:68`, `:187`）は本ラウンドで変更されておらず、テストのアサーションが実装と整合していることも併せて確認した。
