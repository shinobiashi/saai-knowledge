### [G1-1][Copilot][Low][plugins/saai-knowledge/includes/class-markdown-converter.php:349]

`&` と参照名が別のテキストノードに分かれると（`<p>&amp;<span>copy;</span></p>`）、ノード単位の先読みではエスケープできず、`&copy;` と出て © と描画される。/ 判定: 保留（Low）

**対応:** 保留。`escape_text()` の docblock と R1 で既知の制約として記録済み。出るのは文字だけでマークアップにはならない（`<` は常にエスケープするので、ノード境界で HTML が組み上がることはない）。直すには、テキストノードの末尾が `&` + 英数字で終わる場合もエスケープする必要がある。その場合、段落末やタイトル末の `Q&A` まで `Q&amp;A` になり、LLM が読む Markdown の可読性を落とす。ブロックエディターで実体参照の途中だけに書式を付けることはまず無いので、backlog（G1-1（issue-79））へ。/ スレッド: https://github.com/shinobiashi/saai-knowledge/pull/80#discussion_r4240643060

### [G1-2][Copilot][Medium][plugins/saai-knowledge/readme.txt:116]

1.0.3 の Changelog が「any Markdown renderer」と無条件に保証している。コードブロックはエスケープの対象外で、Python-Markdown は標準ではフェンスを認識しないため、コード例の `<script>` は生の HTML になりうる（backlog R2-X1 と同じ事象）。/ 判定: 修正

**対応:** 0ec908e。主張を「投稿のテキストとタイトル」に限定し、コードブロックは変わらずフェンスで出ること、CommonMark 以外のライブラリで HTML に描画するなら HTML をサニタイズすることを追記した（readme パーサーへの影響を避けるため、文中にバッククォート3つは書かない）。/ スレッド: https://github.com/shinobiashi/saai-knowledge/pull/80#discussion_r4240643089
