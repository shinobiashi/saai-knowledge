## 新規指摘

### [R2-1][Low][plugins/saai-knowledge/includes/class-markdown-converter.php:393]

`escape_line_start()` の `>` 分岐は、文字の `>` が `escape_text()` で常に `&gt;` になったため、本文・alt・リンクラベル由来のテキストからは届かなくなった。残る経路は入れ子の `<blockquote>` の内側が出した `> inner` 行だけで、そこで `\> inner` にしてしまう（既知の R1-X3 の原因そのもの）。docblock の「blockquote `>`」も文字の `>` については実態と合わない。更新後の `test_paragraph_starting_with_block_marker_is_escaped` の `&gt; literal` も実際には `escape_text()` の挙動を見ている。

**修正方針:** regex から `>` 分岐を外して docblock を合わせ、入れ子の引用のテストを足す（R1-X3 も同時に解消する）。Low のため backlog へ（R1-X3 と一緒に扱う）。

## 確認した点（抜粋）

- 二重エスケープなし: どの呼び出し元も `escape_text()` を1回だけ、デコード済みの文字列に掛けている。`Export` の `content_markdown` は `Markdown_Output::render()` の結果をそのまま使う
- 置換順の境界: 足した `&lt;` / `&gt;` は `&` で始まるので、前にある未エスケープの `&` と結合して新しい文字参照の形を作らない
- 強調の flanking 判定は、句読点（`<` `>` `&`）が句読点（`&`）に置き換わるだけなので変わらない
- DOMDocument が無い環境のフォールバック（`fallback_plain_text()`）が残す `&lt;b&gt;` と、DOM 経路の出力が同じ形になった
- ドキュメント（DESIGN §7.3・DESIGN-HOOKS-API・CLAUDE.md・readme 1.0.3・backlog）は新しい実装と一致する
- `>` を常に `&gt;` にする副作用（`->` が生の Markdown 上で `-&gt;` になる）は、R1 でユーザーが選んだトレードオフとして確認のみ
