## 指摘

### [R1-1][Medium][plugins/saai-knowledge-for-woocommerce/includes/class-export-metadata.php:128-135]

`_prime_post_caches()` の後に ID ごとの `get_post()` で判定しているが、`WP_Post::get_instance()` は「見つからなかった」ことをキャッシュしないため、完全削除された商品の ID は 1 件ごとに追加のクエリになる。§6.1 の規約で紐づけ ID は勝手に消さず、ゴミ箱は既定 30 日で自動的に完全削除されるので、運用とともに増える。実測: 生きた商品 1 件の紐づけで 3 クエリ、そこに完全削除の ID が 5 件混ざると 8 クエリ（5000 件の CSV では件数倍）。コメント「投稿 1 + メタ 1」も成り立たない。（独立レビューは Low としたが、N+1 は重大度定義上 Medium、かつ時間とともに必ず発生するので引き上げた）

**修正方針:** `get_posts()`（`post__in` + `post_type` / `publish` / `has_password => false` + `orderby => post__in`、メタだけ温める）の 1 クエリで、公開判定と存在確認を SQL 側で済ませる。存在しない ID を混ぜてもクエリ数が増えないことをテストで固定する
