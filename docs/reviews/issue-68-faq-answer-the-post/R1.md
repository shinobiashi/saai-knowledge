## 確認した前提（実ソース）
- `setup_postdata()` → `WP_Query::setup_postdata()` は9グローバルを代入したあと `do_action_ref_array( 'the_post', ... )` を呼ぶ。`WP_Query::reset_postdata()` も「`$GLOBALS['post']` 代入 → `setup_postdata()`」の順で、今回の修正と同じ規約
- WooCommerce 11.2 で `the_post` に掛かっているのは `wc_setup_product_data()` だけ。`ProductDetails::render_tabs()` / `ProductTemplate` は `the_post()` ループで描画し、戻り先は「直前の投稿」で正しい
- 無料版自身は `the_post` にフックしていない。faq-list のネストは `is_rendering()` ガードで止まるため、再発火から再帰する経路はない

## 指摘
### [R1-1][Medium][plugins/saai-knowledge/tests/test-faq-list.php:320]
追加したテストは、戻り先が「直前の投稿」であることと、「再発火 → スナップショット書き戻し」の順序を固定していない。`setup_postdata( $previous_post )` を `wp_reset_postdata()` に変えても、書き戻しとの順序を入れ替えても、全テストが通る。`go_to( page )` の直後は直前の投稿とメインクエリの投稿が同じで区別できず、`POSTDATA_GLOBALS` の値も検証していないため（サブエージェント指摘）。
**修正方針:** Query Loop アイテムを現在の投稿にし、`$page` / `$numpages` にセンチネルを入れたテストを追加する。Cookie を付けて非キャッシュ経路であることを明示する。
