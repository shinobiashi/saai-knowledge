## 指摘

### [R1-1][Medium][.github/workflows/release-woo.yml:34-39]

`contents: write` のトークンが、第三者のコードが走る手順（`npm ci` のライフサイクルスクリプト・`npm run build`・`wp-scripts plugin-zip`）から読める。ジョブの `env:` に `GH_TOKEN` があり、`actions/checkout@v5` は既定（`persist-credentials: true`）で同じトークンを `.git/config` に残す。漏れれば draft を Publish でき、有料版の ZIP が公開される（自己レビュー・独立レビューの両方で検出）。

**修正方針:** checkout に `persist-credentials: false`、`GH_TOKEN` は gh を使う手順の `env:` だけに置く（ジョブを分けると artifact での受け渡しが要るので 1 ジョブのまま）。

### [R1-2][Medium][.github/workflows/release-woo.yml:84-90]

最後の確認は、タグ名の URL（`releases/download/<tag>/…`）が 404 であることしか見ていない。この URL は Release が無くても 404 で、作った Release が draft であることも、draft の添付の URL（`untagged-…` 形式のはず）が閉じていることも確かめていない（独立レビューが、存在しないタグの URL で 404 を実測）。

**修正方針:** `gh release view --json isDraft,assets` で draft であること・添付が 2 つであることを確かめ、各添付の `url` にログインしていない curl をかけて 404 であることを確かめる。

### [R1-3][Medium][.github/workflows/release-woo.yml（全体）]

タグのコミットが main に含まれるかを確かめていない。ドキュメントは「main の版数を揃えたコミットにタグを付ける」としているが、マージ前のブランチのコミットにタグを付けても、そのまま提出用の ZIP ができる（独立レビューは Low〔S-L3〕、自己レビューは Medium。提出物が main と食い違う誤りは Issue の目的〔アップロードした ZIP を既知の状態に結び付ける〕を損なうので Medium とする）。

**修正方針:** compare API（`main...<commit>` の `status` が `identical` / `behind` なら main 上）で確かめ、main に無ければ `::warning::` と Release の本文の先頭の CAUTION で知らせる。失敗にはしない（PR ブランチでの試しタグの運用と両立させるため）。

## Low（backlog へ）

- [R1-L1][Low][.github/workflows/release-woo.yml] 既存 Release の確認が、API・認証の失敗でも「Release なし」として先へ進む（`> /dev/null 2>&1` で終了コードしか見ない）。その場合、同じタグの draft が 2 つできうる
- [R1-L2][Low][.github/workflows/release-woo.yml] 添付のアップロードが途中で失敗すると不完全な draft が残る（`--draft` 指定時、gh は後片付けをしない）。公開はされず、再実行は既存 Release の確認で止まる。手で消す手順がドキュメントに無い
- [R1-L3][Low][bin/verify-woo-zip.sh] macOS の bash 3.2 では、`--notes` の書き込みに失敗してもエラーを 1 行出して `OK`・exit 0 になる（CI の bash 5.2 では exit 1）
- [R1-L4][Low][bin/verify-woo-zip.sh] オプションの値が `-` で始まっても受け取る（`--notes --tag` は `--tag` という名前のファイルを作る）。同じオプションを 2 回渡すと後の値が黙って使われる
- [R1-L5][Low][bin/verify-woo-zip.sh] シンボリックリンク経由で呼ぶと `dirname "$0"` がリンクの置き場所を指し、`--notes` の `git rev-parse` が失敗する。手元で ZIP を組んだ後に HEAD が動くと、notes のコミットが ZIP と食い違う
- [R1-L6][Low][.github/workflows/release-woo.yml] `concurrency:` が無い。同じタグを短い間隔で消して push し直すと、2 つの run が既存 Release の確認を両方通りうる
