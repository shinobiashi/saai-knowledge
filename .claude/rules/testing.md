# テスト（PHPUnit / E2E）

- PHPUnitテストクラス（`WP_UnitTestCase` 継承）は非名前空間の `Test_*` 慣習に従う。WPCSの `PrefixAllGlobals` sniff は既知のユニットテスト基底クラスを継承したクラスを prefix 規約の対象外にするため、`saai_`/`SAAI\Knowledge` prefix は不要。
- WP core test framework は各テスト後に `tear_down()` で登録済みメタキーを全て消去する（`unregister_all_meta_keys()`）。`register_post_meta()` に依存するテストは、ブートストラップ時の `init` 一度きりの登録に頼らず、テストクラスの `set_up()` で明示的に再登録する。
- `composer test`（PHPUnit）を wp-env の `tests-cli` に対して実行すると、テストサイトのDBがWP coreのテストブートストラップにより再インストールされ、全プラグイン（WooCommerce・有料版を含む）の有効化状態と `permalink_structure`（パーマリンク設定）がリセットされる（有効なテーマも無くなる）。同じ `tests-cli`（ポート10031）に対してPlaywright E2E（`npm run test:e2e`）を実行する場合、直前に `composer test` を走らせていたら、`wp plugin activate woocommerce saai-knowledge saai-knowledge-for-woocommerce`・`wp theme activate twentytwentyfive`・`bash bin/wp-env-configure-permalinks.sh` を実行し直してからでないとCPT/タクソノミーのREST・pretty permalink URLが404/`rest_no_route`になり、商品ページも出ない。テーマが無いとブロックのエディター用スクリプトの URL が `themes/default/var/www/html/wp-content/plugins/…` に化けて 500 になり、自分で `activateTheme()` しない spec（`faq-list-category.spec.js`。ファイル名順で最初に走る）はブロックが登録されず落ちる（1.0.3 のリリース前確認で発生。CI は毎回まっさらな環境なので起きない）。
- CI の PHPUnit ジョブは JS ビルドなしで走る（`build/` は gitignore）。`Blocks::register_blocks()` は `build/{block}/block.json` が無いブロックを黙ってスキップするため、実ブロックを `do_blocks()` で描画するテストはローカル（build あり）でだけ通り、CI の全マトリクスで落ちる。テストでは `src/<block>/render.php` を require する `render_callback`（+ `uses_context`）でブロックを登録し、finally でレジストリを復元する（test-shortcodes.php / test-faq-list.php の確立パターン）。検証は `mv build build.bak` で CI 状態を再現してから行う。
- `WP_UnitTestCase` は各テスト後に DB を `ROLLBACK` し、次のテスト開始時（`set_up()` が呼ぶ `clean_up_global_scope()`）にオブジェクトキャッシュもフラッシュするため、`update_option()` 等のテスト内での変更は手動での復元が不要（レビューbotに誤検知として指摘された実績あり）。
- `WP_UnitTestCase::tear_down()` は `post` と postdata 系グローバル（`id`/`authordata`/`page`/`numpages` 等）を null に戻すので、テスト内で代入した分の後始末は不要。`the_post` 再発火の戻り先を検証するテストは、`go_to( page )` 直後だと直前の投稿とメインクエリの投稿が同じになり `wp_reset_postdata()` と区別できない。別の投稿を `$GLOBALS['post']` に置き、`$page` 等にセンチネルを入れて書き戻しの順序まで固定する（`test_items_restores_the_previous_post_rather_than_the_main_query_post()`）。
- `wp_insert_post()` はデフォルトの（`unfiltered_html` 権限を持たない）テストユーザーだと `content_save_pre` の `wp_filter_post_kses()` で `<script>`/`<style>` 等のタグを保存時に除去する（内容は残り、タグだけ消える）。これらのタグを含む生HTMLの挙動をテストする場合は投稿保存を経由せず、対象の処理関数へ直接HTML文字列を渡す。
- テスト側で `set_up()` ごとに `new Service(); ->register();` して `the_content` 等の共有フックに独自登録すると、`Plugin::boot()`（`plugins_loaded`、テストプロセス全体で1回だけ発火）が既に同じサービスを登録済みの場合、同一フックに2つのインスタンスが登録され、片方の出力がもう片方の入力として二重処理される。この不具合はキャッシュキーが粗いと偶然キャッシュヒットで隠蔽されうる（`Autolinker` のキャッシュキー修正で実際に顕在化した）。直接メソッド呼び出し用のインスタンスは `register()` を呼ばない。
- `Plugin::activate()` のような、`flush_rewrite_rules()` 等でグローバルオブジェクト（`$wp_rewrite` 等）を広範に変更するメソッドをPHPUnit内で直接呼ぶテストは、個別プロパティだけでなく対象オブジェクト全体を `clone` で保存し丸ごと復元しないと、同一プロセス内の他のテストへ副作用が漏れる（実際に `Test_Template_Loader` のテスト10件超が巻き添えで壊れた実績あり）。
- PHPUnitテストで「フックが未登録なら一時的に登録する」パターン（`has_filter()` が `false` ならテスト用に `add_action()` する等）を使う場合、後始末は「登録されている状態に戻す」だけでは不十分。元々未登録だった場合はテスト自身が追加したフックを `remove_action()` で確実に取り除き、元の「未登録」状態まで正確に復元する（自分が追加したかどうかを別変数で追跡して分岐する）。さもないと、対象コードがそのフックを実際に取り除いた場合にだけ再登録されてしまい、テスト実行順序に依存する形で後続テストへ状態が漏れる。
- 固定の英語文言（HTML特殊文字を含まない）に対する `esc_html()` 呼び出しをPHPUnitで検証する場合、`esc_html(文言) === 文言` となるため `esc_html()` を外しても同じアサーションが通ってしまう。`gettext` フィルターで一時的に `<script>` 等を含む翻訳へ差し替えてから出力を検証すると、エスケープの有無を実際に検知できる（`Test_Bootstrap::test_missing_woocommerce_notice_is_capability_gated_and_escaped()` が確立パターン。Copilotレビューで指摘）。
- `WP_UnitTestCase::go_to()` はオブジェクトキャッシュを flush する（`flush_cache()`）ので、キャッシュヒットを再現するテストは同一「リクエスト」内で `go_to()` を挟まずに 2 回描画する。また `rest_route` は `tear_down()` が `$wp = new WP()` で作り直した後は public query var ではなく、`go_to( '?rest_route=…' )` は home クエリと等価になる（プロセス先頭で走れば `rest_api_loaded()` が serve して die する実行順依存）。REST block-renderer の状態は `$GLOBALS['wp_the_query'] = $GLOBALS['wp_query'] = new WP_Query()` + グローバル `$post` のプライムで直接作る。
- Playwright（`@wordpress/e2e-test-utils-playwright`）: `locator.filter({ has })` の内側ロケーターは外側から chain せず page 起点で書く（chain すると各候補の内側で祖先条件を再要求して 0 件になる）。ツールチップが開くとアンカーを覆い `hover()` が「intercepts pointer events」で永久に再試行するので `hover({ force: true })`。Interactivity API のトグルはハイドレーション前のクリックが空振りするため `expect(async () => {...}).toPass()` でクリック→`aria-expanded` を再試行。Site Editor を操作する `beforeAll` は既定 30 秒を超えるので `test.setTimeout()` を伸ばす。`admin.visitSiteEditor()` はブロック一覧が落ち着く前に返り、直後の `replaceBlock()` はエディターのリセットで捨てられるため、`editor.canvas` にそのブロックが描画されるまで待ってから操作する。Save ボタン等の util は英語 UI 前提（dev サイトは `ja` なので E2E は tests サイトで）。管理者以外のロールの E2E はログイン画面の「Log In」クリックに頼らない（CI でクリックがフォーム送信にならず 3 回ともタイムアウトした）。`RequestUtils.setup( { user, baseURL } ).login()` → `request.storageState()` を `browser.newContext( { storageState } )` に渡す（グローバルセットアップと同じ方式）。新規作成したユーザーでエディターを開くと、`admin.editPost()` がブラウザ側で閉じた Welcome ガイドを後から届くサーバー保存の設定が上書きして再表示させるため、先に `RequestUtils#setPreferences( 'core/edit-post', { welcomeGuide: false } )` でサーバーへ保存する。保存はラベルが投稿ステータスと UI 言語で変わる Save ボタンではなく `wp.data.dispatch( 'core/editor' ).savePost()` → `didPostSaveRequestSucceed()` で行う（`linked-products-panel.spec.js`）。`<script>` の中身（JSON-LD）は `hasText` / `getByText` の照合対象外なので、`evaluateAll` で `textContent` を数える。
- `npm run lint:js` は各プラグインの `src` だけが対象で、`tests/e2e/*.spec.js` は CI で lint されない（backlog R1-X2（issue-76））。spec は手で `npx wp-scripts lint-js <ファイル>` にかける。`--fix` は**ファイルの後ろ**に置く。`lint-js --fix <ファイル>` だと `<ファイル>` が `--fix` の値として解析され（minimist）、ファイル指定なし＝カレント配下すべてが自動修正される（#76 で無関係の 8 ファイルが書き換わった）。
- 別プラグインのコードを複製したときの照合テストは、同じ入力の結果を比べるだけでは足りない。PCRE は版によって `\p{Katakana}` などを Script_Extensions で照合するので、文字クラスを狭める・広げる改変が結果を変えずに通ってしまう。定数は `ReflectionClassConstant` で、メソッドの本体は `token_get_all()` のトークン列（空白・コメントを除く）で比べ、呼び出し側が渡す値（抜粋の長さなど）も比べる（`plugins/saai-knowledge-for-woocommerce/tests/test-woo-plain-excerpt.php`、#89 R1-1・G1-2）。
