`}` のバックスラッシュエスケープと、`<` / `>` / 文字参照の形の `&` の文字参照化）を一律適用する。`{` / `}` は Python-Markdown の `extra`（attr_list）が見出しの末尾やインライン要素の直後の `{: onclick=… }` をその要素の属性として読むため（Issue #82。`\{` は `\<` と違ってどの方言でもエスケープになる）。またリンク/画像のdestination（href/src）を生のURLのまま `(...)` に埋め込むと、URLに `)` が含まれる場合にリンクが途中で途切れる。CommonMarkの `<...>` 山括弧形式（`<`/`>` のみエスケープすればよい）で包む（`Markdown_Converter::escape_text()` / `markdown_link_destination()` が確立パターン）。`escape_text()` は `<` / `>` を常に `&lt;` / `&gt;` にし、`&` は文字参照の形（`&name;` / `&#123;` / `&#x1F;`）のときだけ `&amp;` にする。`\<` / `\&` のバックスラッシュエスケープは CommonMark でしか効かず、Markdown.pl・PHP Markdown・Python-Markdown では `\<script>` が生の要素と余計な `\` になる（Issue #79 のレビューで Python-Markdown 3.11 により実測）。`<` を「後ろが英字・`/`・`!`・`?` のときだけ」の条件付きにすると、空のインライン要素で `<` と `script>` の2つのテキストノードに分かれた入力を見逃す（連結すると `<script>` になる）。`&` を常にエスケープしないのは、`Q&A` のような頻出の表記を汚さないため（文字参照は文字になるだけでマークアップにはならない）。`&` の置換は `<` / `>` の置換より前に行う（後にすると、足した `&lt;` の `&` まで `&amp;` になる）。そのため `escape_text()` にはデコード済みのプレーンテキストを渡す。ターム名は保存時に HTML エスケープされている（`Q&amp;A`）ので、デコードせずに渡すと文字どおり「&amp;」と出る（Issue #79）。コードは CommonMark のフェンス（```` ``` ````）で出すが、Python-Markdown は拡張なしではフェンスを解釈せず、`fenced_code` / `extra` があってもフェンスと ATX 見出しを行頭（0 桁目）でしか認識しない（CommonMark は空白3つまで許す）。`\~` もエスケープにならず、数字の前の `\` はそのまま見える。そのため、ブロックの行頭に付いた空白と本文の行頭の `~~~` は Python-Markdown で、インライン要素の直後で行の途中から始まるフェンスは CommonMark でも、コード例の - `WP_REST_Server::serve_request()` はREST APIの全レスポンスに自動で `X-Content-Type-Options: nosniff` を付与するが、`template_redirect`/`admin-post.php` 経由で手動生成する非HTML生レスポンス（Markdown/CSV/NDJSON等）にはこの恩恵が無い。ブラウザのMIMEスニッフィング対策として、こうした手動レスポンスには明示的に `header( 'X-Content-Type-Options: nosniff' )` を追加する。
- CSVエクスポート機能で投稿タイトル・本文・タクソノミー名のような編集可能な文字列を出力する場合、セル値の先頭が `=`/`+`/`-`/`@`（および タブ・CR・LF）だと、Excel/Google Sheets/LibreOffice等がそのセルを数式として解釈しうる（CSV/DDE Formula Injection、CWE-1236）。`fputcsv()` 自身のクォート処理はCSV構文上のエスケープであり、スプレッドシートアプリによる数式解釈を防がない。OWASP推奨のとおり、該当する先頭文字を持つ値にはシングルクォート `'` を前置する（`Export::escape_csv_formula()` が確立パターン）。
- PHP 8.4 は `fputcsv()`/`str_getcsv()` の `$escape` パラメータを省略するとDeprecation警告を出す（将来のバージョンでデフォルトが `"\\"` から `""` に変わる予告）。省略せず明示的に渡す（`$escape` に `''` を指定するとRFC 4180準拠の「囲み文字を2重化するだけ」のクォート方式になり、Excel/Pythonのcsvモジュール等ほとんどの実装の前提と一致する）。この警告メッセージ自体もやっかいで、PHPUnitテスト内で `ob_start()`/`ob_get_clean()` により出力をキャプチャしているコードパスで `fputcsv()`/`str_getcsv()` を呼ぶと、警告テキストがそのキャプチャしたバッファに混入し、行の実際の値がズレて原因不明のアサーション失敗を起こす（PHP 8.4のCIマトリクスだけ失敗する形で顕在化した実績あり）。
- `WP_Date_Query`（`date_query` 引数）の `after`/`before` に文字列を渡すと、`build_mysql_datetime()` は（`'Z'` や明示的なオフセット付きでも）その値を一度 `wp_timezone()`（サイトの設定タイムゾーン）へ変換してから、タイムゾーン情報を持たない `Y-m-d H:i:s` 形式の文字列へ戻す。この値を `post_modified_gmt` のような真のUTC列と比較すると、サイトのUTCオフセット分（例: Asia/Tokyoなら9時間）だけ境界がずれ、その間に更新された投稿が増分同期から永久に欠落しうる。UTCの絶対時刻をUTC列と正しく比較したい場合は、文字列ではなく `year`/`month`/`day`/`hour`/`minute`/`second` の配列を渡す——`build_mysql_datetime()` は配列入力の場合はこのタイムゾーン変換ロジックを完全にバイパスし、渡した数値をそのままSQLへ使う（`Export::query_records()` で実例。Codexレビューで指摘・Asia/Tokyo設定のwp-envで再現・修正確認済み）。
- `WP_Query` の `orderby` は `post_modified_gmt`/`modified_gmt` のような `_gmt` 列を直接指定できない（`WP_Query::parse_orderby()` の `$allowed_keys` に存在するのは `modified`＝サイトローカルの `post_modified` のみ）。`_gmt` 列基準で厳密にソートしたい場合（`date_query`/フィルターが `_gmt` 列を使っているのに合わせる等）は、そのクエリだけに限定した `posts_orderby` フィルターを `new WP_Query()` の直前で `add_filter()` → 直後に `try/finally` で `remove_filter()` する。フィルター内では対象のクエリだけを識別するため `$query_args` に独自のマーカー（例: `'saai_export_query' => true`。WP_Query はバリデーションせずそのまま保持するので公開クエリ変数として登録する必要はない）を仕込み、`$query->get('marker_key')` で確認してから上書きする。他プラグインが同じフックへ既定優先度10で登録している可能性があるため、優先度は10より遅く（例: 20）して自分が最後に勝つようにする（`Export::order_by_modified_gmt()` が確立パターン。DSTのあるタイムゾーンで `post_modified` と `post_modified_gmt` の大小関係が逆転しうることが実際の動機——Copilotレビューで指摘）。
- リクエストコンテキストに応じて処理をスキップする既存の仕組み（例: `Autolinker::process_content()` が `REST_REQUEST`/`is_admin()`/`is_feed()` 中は無条件にスキップする）の**下流**にある処理結果を、別の（スキップされない）コンテキストとも共有するキャッシュへ書き込むと、どちらのコンテキストが先にそのキャッシュを埋めるかによって出力内容が変わってしまう（例: REST経由のエクスポートが先に走ると、後続の通常ページ表示が本来受け取るはずのオートリンク付きMarkdownの代わりに、オートリンクなしの版を最大1日間キャッシュTTL分だけ受け取り続ける）。新しい呼び出しコンテキストから既存の共有キャッシュ関数（例: `Markdown_Output::render_cached()`）を流用する前に、その戻り値がコンテキスト依存のロジックを経由していないか確認し、経由している場合はキャッシュを書かない非キャッシュ版（例: `render()`）を使う（`Export::build_record()` で実例。Codexレビューで指摘）。
